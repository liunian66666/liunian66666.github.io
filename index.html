BEHIND THE WORK

不止于演示.

这些项目里的共同方法，是让模型输出能够连接证据、业务规则与可重复的检查。

01 / EVIDENCE

让回答有来源

检索结果保留出处与适用范围。缺少可信知识时，明确表达未知，而不是填补一个看似完整的答案。

02 / CONTROL

让操作有边界

涉及订单、退款或邮件等实际动作时，把身份、工具规则与人工确认放在执行路径里。

03 / VERIFICATION

让效果可复核

通过测试、评测样本与执行轨迹检查系统表现，同时写清演示数据和真实业务接入之间的界限。

PROJECT NOTES

项目背后的具体工作

01

AI Customer Service

在 原开源项目 的多租户架构上，重点完善电商客服 Agent 的身份与业务边界：客户会话令牌、租户和客户维度的订单归属查询、确定性流程 FAQ，以及转人工流程。当前订单使用演示数据；真实订单、支付和退款写入尚未接入。

02

LabPilot

将纪要抽任务、四维待办、进展记录、周报草稿和发送确认串成科研事务闭环。任务与草稿保留原文依据；Zotero 文献检索采用按用户绑定的只读凭证。项目是个人原型，邮件验收使用模拟发送。体验示例数据预览 ↗ · 查看源码 ↗

03

Support Agent

新版在本机完成四服务 Compose 验收：审核 FAQ 与适用范围、Redis 精确缓存和受限语义复用、Milvus 分范围检索；订单查询读取演示业务库，退款和支付经过人工审批、参数绑定的幂等处理。会话与审批检查点可在后端重启后恢复，转人工工单支持接单和关闭，trace 关联证据、缓存、工具及业务结果。最终本地回归 421 项通过，并完成实际请求、重启和依赖故障演练。线上 Streamlit 入口仅供体验，不能据此认定已部署同一新版；订单、支付和退款仍为演示数据，未接入真实交易渠道。

04

Code Review Agent

围绕 PR 变更建立文件分流、逐文件分析、结构化问题输出和结果持久化流程。FastAPI 接收任务，Celery 异步执行，LangGraph 管理审查状态；这是本地项目，页面未提供未经核实的在线服务入口。

05

DeepEye-SQL · 智能数据分析助手

在开源 DeepEye-SQL 研究项目基础上，完成面向应用的工程扩展：接入 OpenAI 兼容模型与云向量服务，将多阶段流程封装为单题 SQLSkill，提供 FastAPI + SSE 演示页，并限制为已注册数据库的只读查询、执行超时、返回行数及请求预算。固定 50 题、5 个数据库的本地对照中，完整流程集合式执行正确率为 76%，仅生成方案为 72%；这是小样本工程验证，不代表官方 BIRD 榜单成绩。当前为本地单用户演示，串行处理请求，尚无公开部署入口；上游算法与论文成果归原作者。
